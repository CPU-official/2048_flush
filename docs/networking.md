# 네트워크 (서버 모드 / LAN 멀티플레이 / 중앙 랭킹)

행사장 내부 LAN에서 **지정한 부모 PC 한 대가 모든 서버 역할**(1대1 대결 매칭, 랭킹 저장, 설정 배포)을 맡고, 나머지 PC는 그 PC에 접속하는 클라이언트로 동작한다. 전용 서버 장비는 필요 없다.

화면과 계정 규칙은 [overview-project.md](overview-project.md), 폴더 구조는 [tech-stack.md](tech-stack.md)를 본다.

## 전제

- 대상은 Windows / macOS Electron 앱뿐이다. 브라우저 접속은 지원하지 않는다.
- 보안은 고려하지 않는다 (내부망 행사용). 인증, 암호화, 점수 검증, 비밀번호 해시는 구현하지 않는다. 비밀번호는 평문 저장.
- 단, 비밀번호는 서버 밖으로 나가지 않는다 (어떤 응답, CSV, 화면에도 표시하지 않음).
- 인터넷 연결 없이 동작한다.
- 멀티플레이는 **1대1 대결**(같은 시드, 더 높은 점수가 승리)만 지원한다. 공격전, 협동, 3인 이상은 제외. 화면과 규칙은 [overview-project.md](overview-project.md)의 "대결 화면"을 따른다.

## 역할: 서버 모드 / 클라이언트 모드

같은 앱(같은 빌드)을 설정으로 전환한다.

| 모드 | 대상 | 하는 일 |
|---|---|---|
| **서버 모드** | 부모 PC 1대 | 서버 실행 (랭킹, 대결 매칭, 설정 배포). 본인도 localhost 클라이언트로 플레이 가능 |
| **클라이언트 모드** (기본) | 나머지 PC | 서버 주소로 접속해서 랭킹 조회/등록, 멀티플레이 참가 |

```
[부모 PC: 서버 모드 Electron]
  ├─ 랭킹 저장소 (JSON 파일)
  ├─ 서버 설정 (수당 제한 시간 등)
  └─ 대결 매칭 / 입력 중계 (WebSocket, ws)
        ↑ ws
[참가 PC들: 클라이언트 모드 Electron]
```

- 클라이언트끼리 직접 연결(P2P)하지 않는다. 모두 서버 PC에만 접속한다.
- **관리 기능(랭킹 초기화, 사용자 삭제, 비밀번호 재설정, 제한 시간 변경)은 서버 PC의 앱에서만 실행한다.** ws 메시지로 노출하지 않으므로 클라이언트가 호출할 수 없다.

## 서버 지정 / 접속 방법

서버 PC는 시작 시 `IP:포트`를 화면에 크게 표시한다. 클라이언트는 그 주소를 설정 화면에서 직접 입력한다 (MAC 주소, 자동 검색, QR코드는 지원하지 않는다). 서버 PC는 **고정 IP**로 두거나, 바뀌어도 설정에서 쉽게 수정할 수 있게 한다.

### 설정 화면

[overview-project.md](overview-project.md)의 설정 화면을 따른다.

### 슬래시 커맨드 (서버 모드 PC에서만 동작)

시작 화면에서 `/` 키로 입력창을 연다 (`Esc`로 닫는다). 설정 화면 버튼과 같은 서버 함수를 호출한다.

- 입력창은 **시작 화면만 보일 때(설정·랭킹 팝업이 없을 때)만** 열린다. 열린 채로 화면의 어떤 버튼이든 누르면 닫힌다. 실행 중에는 Enter를 다시 눌러도 무시한다. 다른 입력칸에 `/`를 칠 때는 열리지 않는다. 열면 `/`가 미리 들어 있고, 명령을 실행하면 결과 한 줄이 아래에 표시된다.
- 명령 문자열을 관리 함수 호출로 바꾸는 일은 순수 함수 `parseCommand`(`src/ui/console/parse.ts`)가 한다. 명령어와 하위 명령은 대소문자를 가리지 않는다. 모르는 명령이나 틀린 인자는 실행하지 않고 명령 목록을 안내한다.
- `/server start abc`처럼 포트가 숫자가 아니면 그대로 넘겨 관리 함수의 포트 검증이 거부한다.
- 운영 명령(`/server status`, `/ranking ...`)은 서버가 이 PC에서 실행 중일 때만 동작하고, 아니면 관리 함수가 이유를 돌려준다.

| 명령 | 동작 |
|---|---|
| `/server start [포트]` | 이 PC를 서버로 시작 |
| `/server stop` | 서버 중지 |
| `/server status` | 접속자 수, 대기 중인 사람, 진행 중인 대결 목록, 서버 IP 표시 |
| `/connect <ip[:포트]>` | 해당 서버에 클라이언트로 접속 (모든 모드) |
| `/disconnect` | 접속 해제 (모든 모드) |
| `/ranking export` | 랭킹을 CSV로 내보내기 (비밀번호 제외) |
| `/ranking reset` | 확인 안내만 표시 (실행 안 함) |
| `/ranking reset confirm` | 현재 랭킹을 백업 파일로 복사한 뒤 초기화 |

### 설정 저장

**이 PC 설정** — Electron `userData` 경로의 `config.json`:

```json
{ "mode": "client", "serverAddress": "192.168.0.10:8080", "port": 8080, "vfx": true }
```

**서버 설정** — 서버 PC의 `userData/server-settings.json`:

```json
{ "timer": { "start": 3.0, "maxReduction": 2.0, "midMove": 40, "steepness": 0.1 } }
```

- 두 파일 모두 없으면 기본값으로 동작한다. 일부 값만 적혀 있으면 나머지는 기본값을 쓴다.
- `mode`가 `"server"`이면 앱을 켤 때 `port`로 서버를 띄우고, 서버가 뜨면 이 PC의 클라이언트는 `localhost:포트`로 접속한다. 포트 충돌이나 깨진 데이터 파일(`ranking.json`, `server-settings.json`) 때문에 서버가 뜨지 못해도 창은 열리고 싱글 플레이는 된다. 깨진 `ranking.json`은 덮어쓰지 않고 그대로 둔다.
- `config.json`이 깨져 있으면 기본값(클라이언트 모드)으로 켜진다.
- 서버는 처리하다 오류가 난 메시지를 버리고 계속 동작한다 (메시지 하나 때문에 행사 중 서버가 죽지 않게).
- 서버가 실행 중이 아니면(`mode`가 `"client"`이거나 서버가 뜨지 못한 경우) `serverAddress`로 접속한다. 비어 있으면 접속하지 않는다.
- 모드는 따로 고르지 않는다. **서버를 시작하면 `mode`가 `"server"`로, 중지하면 `"client"`로 저장된다.** 그래서 서버를 켜 둔 채 앱을 껐다 켜면 서버가 다시 뜬다.
- 서버 실행 중에는 `serverAddress`가 저장돼 있어도 쓰지 않는다. 서버를 중지하면 다시 그 주소로 접속한다.
- 이 파일들은 설정 화면이 고친다. 손으로 고칠 일은 없다.

### 관리 함수 (`electron/admin.ts`)

설정 화면 버튼과 슬래시 커맨드가 부르는 함수를 한 곳에 모아 둔다. 렌더러는 preload의 `window.api.admin(이름, ...인자)` 하나로 호출하고(IPC 채널 `admin`), 모든 함수는 `{ ok, message, state }`를 돌려준다. `message`는 화면에 그대로 보여 주는 문구, `state`는 이 PC의 현재 상태(`src/net/admin.ts`의 `AppState`)다. 렌더러는 돌려받은 `state.connectTo`에 맞춰 접속 대상을 바꾼다.

| 이름 | 인자 | 동작 |
|---|---|---|
| `state` | — | 현재 상태 조회 |
| `server.start` | 포트(생략 시 저장된 포트) | 서버 시작. 포트는 1~65535 정수 |
| `server.stop` | — | 서버 중지 |
| `connect` | `IP` 또는 `IP:포트` | 서버 주소 저장 (포트를 생략하면 `DEFAULT_PORT`, 포트는 1~65535) |
| `disconnect` | — | 서버 주소 지움 |
| `vfx` | `true`/`false` | 이 PC의 VFX on/off 저장 |
| `timer.set` | `{ start, maxReduction, midMove, steepness }` | 제한 시간 저장 (서버 실행 중에만). 검증은 `validateTimer`: 네 값이 모두 숫자, 시작값 > 0, 시작값 - 최대감소값 ≥ `MIN_LIMIT`. 통과하면 `server-settings.json`에 저장하고 접속 중인 모든 클라이언트에 `config`를 다시 보낸다 |
| `user.delete` | 닉네임 | 닉네임과 그 닉네임의 기록을 함께 지운다 (서버 실행 중에만, 백업 없음) |
| `user.password` | 닉네임, 새 비밀번호 | 비밀번호를 4자리 숫자 문자열로 바꾼다 (서버 실행 중에만). 결과 `message`에 비밀번호를 넣지 않는다 |
| `server.status` | — | 서버 주소, 접속자 수, 대기 중인 사람 수, 진행 중인 대결(`닉네임 vs 닉네임`)을 한 줄로 돌려준다 (서버 실행 중에만) |
| `ranking.export` | — | 랭킹을 CSV로 내보낸다 (서버 실행 중에만). 파일 경로를 `message`로 돌려준다 |
| `ranking.reset` | — | 랭킹을 백업한 뒤 초기화한다 (서버 실행 중에만). 확인 절차는 호출하는 쪽이 맡고 이 함수는 항상 백업 후 실행한다 |

- 관리 함수는 호출된 순서대로 하나씩 실행한다 (버튼 연타로 서버가 두 번 뜨지 않게).
- 바뀐 제한 시간은 **다음 게임부터** 적용된다 (클라이언트는 `config`를 받으면 `net.timer`만 갱신하고, 진행 중인 게임의 세션은 시작할 때 받은 값을 계속 쓴다). `state`의 `timer`는 서버가 실행 중일 때만 값이 있다.
- **구현 현황**: 설정 화면과 슬래시 커맨드까지 구현했다.

### 클라이언트 접속

- 접속이 끊기면 `RECONNECT_INTERVAL`(3초)마다 다시 접속을 시도한다.
- 요청(`rank.submit`, `rank.get`)의 응답이 `REQUEST_TIMEOUT`(5초) 안에 오지 않거나 그 사이 끊기면 "서버에 닿지 못함"으로 처리한다.
- 서버가 내려준 마지막 제한 시간 설정은 렌더러의 `localStorage`(`timer` 키)에 보관해, 서버 없이 켰을 때도 그 값을 쓴다.
- 렌더러는 앱 시작 시 관리 함수 `state`를 불러 접속할 주소(`connectTo`)를 받는다.
- **연결 테스트**: 입력한 주소로 임시 WebSocket을 열어 보고 바로 닫는다. `REQUEST_TIMEOUT` 안에 열리면 성공이다. 저장된 주소나 현재 접속에는 영향을 주지 않는다.

## 서버 책임

1. **랭킹**: 닉네임별 기록 저장, 순위 조회 (닉네임 + 비밀번호로 본인 구분)
2. **설정 배포**: 접속한 클라이언트에 제한 시간 설정(`config`) 전달
3. **1대1 대결**: 대기열 매칭, 시드 배포, 입력 중계, 승패 판정
4. **현황**: 접속자, 진행 중인 대결 (선택: 전광판 모드)

## 동기화 방식: 시드 + 입력 전송 (1대1 대결)

보드 상태가 아니라 **시드와 입력만** 주고받는다.

1. 서버가 대결 시작 시 **시드**를 정해 두 사람에게 전달한다.
2. 각 클라이언트는 `core`를 시드 기반 RNG로 실행한다. 같은 시드 + 같은 입력 = 같은 결과.
3. 플레이어가 이동하면 `{ 방향, 턴 번호 }`만 서버로 보내고, 서버가 상대에게 중계한다.
4. 상대 보드는 받은 입력으로 로컬에서 재현해 오른쪽 보드로 표시한다. 점수는 재현한 보드의 점수를 쓴다.

효과: 트래픽이 매우 적고, 내 조작은 네트워크 지연과 무관하게 즉시 반응한다.

### core 요구사항

- `Math.random` 사용 금지. 시드 기반 RNG는 **mulberry32를 직접 구현**한다 (의존성 없음).
- `core`는 렌더링/시간/네트워크에 의존하지 않는 순수 로직으로 유지한다. 제한 시간 타이머는 `core` 밖(`src/game/`)에서 관리한다.
- 같은 시드와 입력 로그를 넣으면 항상 같은 보드가 나와야 한다.
- **리플레이 테스트**: 기록한 이동 로그를 서로 다른 두 `core` 인스턴스에서 재생해 보드가 같은지 비교한다. 재접속 복원(입력 로그 재생)도 같은 테스트로 검증한다.

## 랭킹

### 범위

- 랭킹은 **싱글 플레이 전용**이다. 1대1 대결 결과는 반영하지 않는다.
- 화면은 두 가지다: **전체 순위**(닉네임별 최고 점수 순)와 **개인 기록**(한 닉네임의 게임별 기록).

### 데이터

저장소는 JSON 파일 하나(`ranking.json`)이고, 별도 인터페이스 없이 `load()` / `save()` 함수로 다룬다.

```json
{
  "users": { "홍길동": "0123" },
  "games": [
    { "id": "a1b2c3", "nickname": "홍길동", "score": 20480, "maxTile": 1024, "at": 1731300000000 }
  ]
}
```

### 규칙

- 게임 종료 시 클라이언트가 `{ 게임 id, 닉네임, 비밀번호, 점수, 최대 타일 }`을 서버에 제출한다.
- 점수는 클라이언트가 보낸 값을 그대로 신뢰한다 (재검증 없음).
- **계정**: 처음 보는 닉네임이면 `users`에 등록한다. 이미 있는 닉네임인데 비밀번호가 다르면 `password` 오류로 거부한다. 닉네임과 비밀번호 형식은 서버에서도 검사한다 ([overview-project.md](overview-project.md)의 계정 규칙).
- **중복 방지**: `게임 id`는 클라이언트가 게임마다 만든 랜덤 값이다. 서버는 이미 처리한 id가 다시 오면 저장하지 않고 성공 응답만 돌려준다.
- **저장은 원자적으로**: `ranking.json.tmp`에 쓴 뒤 `ranking.json` 위로 rename한다. 쓰는 도중 종료돼도 파일이 깨지지 않는다.
- **백업**: 서버가 떠 있는 동안 `BACKUP_INTERVAL`(5분)마다 `ranking.json`을 `ranking.backup.json`으로 복사한다 (한 벌만 두고 덮어쓴다). `/ranking reset confirm` 직전에도 반드시 `ranking.<시각>.json`으로 복사한다.
- **CSV 내보내기**: 서버 PC의 `userData/ranking.<시각>.csv`에 쓴다 (시각은 로컬 `YYYYMMDD-HHmmss`). 열은 `닉네임,점수,최대 타일,기록 시각(ISO 8601)`이고 게임 한 줄씩, 점수 높은 순이다. 비밀번호와 게임 id는 넣지 않는다. 엑셀에서 한글이 깨지지 않도록 UTF-8 BOM을 붙이고, 쉼표·큰따옴표·줄바꿈이 든 닉네임은 큰따옴표로 감싼다.
- **초기화**: `users`와 `games`를 **모두** 비운다 (닉네임 등록도 사라지므로 다음 방문자가 같은 닉네임을 새 비밀번호로 쓸 수 있다). 직전의 메모리 상태를 `ranking.<시각>.json`으로 저장하고(같은 초에 이미 있으면 `-1`, `-2`를 붙여 덮어쓰지 않는다), 그 뒤 `ranking.json`을 빈 데이터로 덮어쓴 다음 메모리를 비운다. 접속 중인 클라이언트의 오프라인 큐는 건드리지 않는다.
- **기록 시각**: `games[].at`은 서버가 기록을 받은 시각(서버 시계, ms)이다.
- **정렬**: 점수가 높은 순, 같으면 먼저 기록한 쪽이 위다. 전체 순위와 개인 기록 모두 같다.
- **형식 오류**: 닉네임/비밀번호 형식이 틀렸거나 점수가 숫자가 아니면 `invalid` 오류로 거부하고 아무것도 저장하지 않는다.
- **응답에 넣는 값**: 랭킹 목록의 한 줄은 `{ nickname, score, maxTile, at }`뿐이다. 비밀번호와 게임 id는 넣지 않는다.
- 사용자 삭제는 `users`와 그 닉네임의 `games`를 함께 지운다. 비밀번호 재설정은 `users`의 값만 바꾼다 (기록은 그대로). 둘 다 바로 `ranking.json`에 저장한다.
- 렌더러가 받는 `state.users`는 **닉네임 목록뿐**이다. 비밀번호는 관리 함수의 응답 어디에도 들어가지 않고, 렌더러에서 메인 프로세스로 들어가는 방향(재설정 입력)만 있다.

### 오프라인 큐

서버 연결이 끊겨도 기록이 사라지지 않게 한다.

- 서버에 보낼 수 없으면 결과를 **로컬 큐에 저장**하고, 재접속 시 자동 전송한다. 재전송해도 `게임 id` 덕분에 중복 저장되지 않는다.
- 재접속 후 서버가 `password` 오류로 거부한 항목(오프라인 중 다른 PC에서 같은 닉네임이 먼저 등록된 경우)은 큐에서 제거하고 로컬 로그에 남긴다.
- 서버가 없을 때도 싱글 플레이는 로컬에서 동작한다.
- **저장 위치**: 큐는 렌더러의 `localStorage`(`queue` 키)에 제출 내용 그대로(닉네임, 비밀번호 포함) 둔다. 앱을 껐다 켜도 남는다.
- **큐에 넣는 경우**: 접속이 끊겨 있을 때, 그리고 보낸 뒤 `REQUEST_TIMEOUT` 안에 응답을 받지 못했을 때. 서버가 답한 거부(`password`, `invalid`)는 큐에 넣지 않고 바로 화면에 알린다.
- 접속은 살아 있는데 응답만 못 받아 큐에 남은 항목은 `RECONNECT_INTERVAL`마다 다시 보낸다.
- `localStorage`의 큐나 설정 값이 깨져 있으면 빈 큐/기본값으로 시작한다 (앱이 안 뜨는 일은 없어야 한다).
- **전송**: 접속되면 큐의 앞에서부터 하나씩 보내고, 응답을 받은 항목을 큐에서 뺀다. 거부된 항목은 `console.warn`으로 남기고 버린 뒤 다음 항목을 계속 보낸다.
- 오프라인에서 처음 입력한 계정은 서버 확인 없이 메모리에 유지한다. 게임 오버 팝업에는 "서버에 연결되지 않았어요. 연결되면 자동으로 기록돼요."를 띄운다.
- **연결 상태 표시**: 모든 화면의 오른쪽 위에 "연결됨" 또는 "끊김"을 표시하고, 큐에 기록이 있으면 "· 대기 중 N건"을 붙인다. 서버 주소가 설정되지 않은 PC도 "끊김"으로 표시한다.

## 메시지 프로토콜 (초안)

| 방향 | 타입 | 내용 |
|---|---|---|
| S→C | `config` | `timer`: 제한 시간 설정(`start`, `maxReduction`, `midMove`, `steepness`). 접속 직후 전송 |
| C→S | `match.find` | `nickname` (대기열에 들어감. 앞뒤 공백을 지운 1~`NICKNAME_MAX`자. 이미 대기/대결 중이거나 형식이 틀리면 무시) |
| C→S | `match.cancel` | (대기 취소) |
| S→C | `match.found` | `id`(대결 id), `opponent`(상대 닉네임), `slot`(0 또는 1. 먼저 대기한 사람이 0. 재접속 때 본인을 가리키는 값이라 클라이언트는 메모리에만 보관한다) |
| S→C | `start` | `id`, `seed`, `startIn`(**시작까지 남은 ms**), `timer`(그 시점의 제한 시간 설정), `timeLimit`(대결 시간 상한, 초) |
| C→S | `move` | `dir`, `turn`(0부터. 서버는 값을 검사하지 않고 그대로 중계) |
| S→C | `move` | `dir`, `turn` (상대 입력 중계. 상대에게만 보낸다) |
| C→S | `gameover` | `score`, `maxTile`, `reason`(`stuck`, `timeout`(수당 제한 시간 초과), `matchTime`(대결 시간 상한)) (대결 판정용, 랭킹과 무관) |
| S→C | `match.timeup` | (대결 시간 상한 도달 알림) |
| S→C | `opponent.over` | `score`(상대 최종 점수), `reason` |
| S→C | `opponent.status` | `offline`(끊김) 또는 `online`(복귀) |
| C→S | `match.resume` | `id`, `slot` (재접속 시. 7-B에서 구현) |
| S→C | `result` | `outcome`(`win`/`lose`/`draw`, 받는 사람 기준), `score`(내 점수), `opponentScore`, `reason`(`normal`/`timeLimit`/`forfeit`) |
| C→S | `rank.submit` | 게임 id, 닉네임, 비밀번호, 점수, 최대 타일 (싱글 전용) |
| S→C | `rank.ack` | 게임 `id`, `ok`(성공 여부), 실패 시 `error`(`password` 또는 `invalid`) |
| C→S | `rank.get` | `scope`(`all` 또는 `player`), `nickname`(`player`일 때), `top`(상위 N) |
| S→C | `rank.list` | 요청의 `scope`와 `nickname`을 그대로 돌려주고, `entries`에 랭킹 목록 (비밀번호 제외) |

- 메시지는 JSON, 모든 메시지에 `type`을 둔다. 알 수 없는 타입은 무시한다. 타입 정의는 `src/net/messages.ts`가 기준이다.
- 관리 함수는 호출된 순서대로 하나씩 실행한다 (버튼 연타로 서버가 두 번 뜨지 않게).
- **구현 현황**: `config`, `rank.*`와 대결 서버 쪽(`match.find`/`cancel`/`found`, `start`, `move`, `gameover`, `opponent.over`, `match.timeup`, `result`)까지 구현했다. `match.resume`, `opponent.status`와 부전승(`forfeit`)은 7-B에서 구현한다. 그 전에는 진행 중인 대결에서 연결이 끊겨도 서버가 아무 처리를 하지 않는다 (대기 중이면 대기열에서만 빠진다).
- **시작 시각은 절대 시각이 아니라 "남은 ms"로 보낸다.** PC마다 시계가 달라도 각 클라이언트가 `start`를 받은 시점부터 센다.
- 멀티에서 시간 초과로 끝난 것은 입력이 아니라서 이동 로그에 남지 않는다. 그래서 `gameover`의 `reason: timeout`을 서버가 기록하고, 재접속 시 입력 로그와 함께 "종료됨" 상태를 내려준다.

## 대결 진행 흐름 (1대1)

- 대결 로직은 `electron/server/match.ts`의 순수 함수 `createMatches`(전송, 시계, 난수를 주입받는다)에 있고, `server.ts`가 ws 연결을 연결 id로 이어 준다. 끝난 대결은 정리돼 두 사람 모두 다시 `match.find`를 보낼 수 있다. 서버를 멈추면 진행 중인 대결은 결과 없이 사라진다.

1. 클라이언트가 `match.find`를 보내면 서버가 대기열에 넣는다. 이미 대기 중인 사람이 있으면 **선착순으로 둘을 묶어** 대결을 만든다 (방 코드 없음, 동시에 여러 대결 가능).
2. 서버가 양쪽에 `match.found`를 보낸 뒤 시드를 정하고 `start`를 보낸다 (`start`에는 그 시점의 제한 시간 설정이 들어 있어 두 사람이 같은 규칙을 쓴다).
3. 양쪽이 카운트다운(`MATCH_COUNTDOWN`) 후 **동시 시작**. 이동은 `move`로 서로에게 중계된다.
4. 한 사람이 끝나면 `gameover`를 보내고, 서버가 상대에게 `opponent.over`를 전달한다.
5. **종료 판정**(서버가 한다): 양쪽 `gameover`가 모두 오면 끝낸다. 카운트다운이 끝나 게임이 시작된 때부터 `MATCH_TIME_LIMIT`이 지나면 서버가 양쪽에 `match.timeup`을 보내고, 클라이언트는 현재 점수로 `gameover(reason: matchTime)`을 보낸다. 점수는 클라이언트가 보고한 값을 그대로 신뢰한다 (재검증 없음).
6. 서버가 점수가 높은 쪽을 승자로 하는 `result`를 양쪽에 보낸다. 점수가 같으면 `draw`.

## 예외 처리

- **대결 중 재접속**: 서버가 두 사람의 입력 로그(와 종료 사유)를 보관한다. 끊긴 쪽이 `match.resume`으로 돌아오면 두 로그를 다시 보내 두 보드를 복원한다. 끊긴 동안 상대에게는 `opponent.status: offline`을 보낸다.
- **재접속 시간 초과**: `RECONNECT_WAIT` 안에 돌아오지 않으면 서버가 `result`에 사유 `forfeit`를 담아 남은 사람의 승리로 끝낸다. 그동안 남은 사람은 자기 게임을 계속할 수 있고, 그 점수는 기록하지 않는다.
- **대기열 이탈**: 대기 중에 연결이 끊기거나 `match.cancel`을 보내면 대기열에서 뺀다.
- **서버 이탈**: 진행 중인 대결은 종료된다 (결과 없음). 서버 PC는 절전/자동 업데이트를 꺼 둔다.
- **지연/유실**: WebSocket(TCP)이라 순서가 보장된다. 턴 번호로 중복/누락을 검출한다.
- **방화벽**: Windows/macOS 모두 첫 실행 시 "수신 허용" 팝업이 뜬다. 서버 PC용 안내 문구를 제공한다.

## 기술 선택

- **`ws`**: 가볍고 프로토콜을 직접 정의하기 쉽다. Socket.IO와 Colyseus는 이 규모에 과하다.
- 메시지 타입 정의는 `src/net`에 두고 서버와 클라이언트가 공유한다.

## 성능/VFX 고려

- 풀 이펙트는 내 보드에만 적용하고, 상대 보드는 같은 크기지만 경량 이펙트만 쓴다.

## 환경 점검 (현장 체크리스트)

LAN 환경에 따라 PC 간 접속이 막힐 수 있다. 현장에서 다음을 확인한다.

1. 서버 PC에서 서버 모드로 앱을 시작하고 표시된 `IP:포트`를 확인한다 (`ipconfig` / `ipconfig getifaddr en0`로도 확인 가능).
2. 다른 PC 앱의 설정에서 그 주소를 입력하고 "연결 테스트"를 누른다.

접속이 안 될 때 원인:

| 원인 | 대응 |
|---|---|
| 클라이언트 격리 (AP/스위치) | 관리자에게 해제 요청 |
| 방화벽 정책 (그룹 정책 관리) | 예외 규칙 요청, 허용된 포트(80, 8080 등)로 변경 |
| VLAN 분리 | 같은 대역의 PC끼리만 가능 |
| 앱 실행 제한 | 설치 없이 실행되는 포터블 실행 파일 사용 |

- 포트는 설정에서 변경할 수 있다.
- 개발 환경 내부망에서 PC 간 접속은 확인 완료. 실제 행사/컴퓨터실 네트워크에서는 별도 확인이 필요하다.

## 미정 사항

- 서버 모드 PC를 서버 전용(전광판 모드: 접속 현황과 랭킹을 크게 표시)으로도 쓸지. 현재 설계는 서버 PC도 플레이 가능하도록 둠.
- (동시 대결 수 상한은 두지 않는다. 메시지가 작아 부하가 문제될 가능성이 낮으며, 실제 행사에서 문제가 보이면 추가한다.)
